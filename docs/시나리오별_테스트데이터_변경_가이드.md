# 시나리오별 테스트 데이터 변경 가이드

가상 차량의 데이터를 adb로 바꿔 사용자 상황을 재현하는 가이드입니다. 테스트할 시나리오를 고른 뒤 **준비 상태 → 데이터 변경 → 사용자 응답 → 결과 확인** 순서로 진행합니다. 각 시나리오는 독립 테스트이며, 문서 전체를 연속 실행하는 방식이 아닙니다.

## 기본 차량 구성

그룹은 내 차와 가상 차량 2대로 구성됩니다. 외부 DB 없이 앱 메모리에서 가상 차량의 이동·상태·제안·메시지를 관리합니다.

| 차량 | 데이터 출처 | 초기 목적지 | 초기 경유지 | 에너지 |
|---|---|---|---|---|
| **나** | 내 차 Pleos SDK | 현재 내비 설정 | 현재 내비 설정 | SDK 조회값 |
| **언니네** (`sister`) | 목업 | 강릉역 | 문막휴게소 | EV 배터리 62% |
| **부모님** (`parents`) | 목업 | 강릉역 | 없음 | 연료 48% |

가상 차량은 시간이 지나면 위치와 남은 거리가 변합니다. **내 차는 `reset`으로 초기화되지 않습니다.** 추천 테스트에서는 내 차 내비 목적지도 강릉역으로 맞춥니다.

## 실행 준비

[README](../README.md)의 설정·설치를 마친 뒤 앱을 실행합니다. 모든 명령은 **user 10** 기준이며, 앱이 열린 것을 확인한 뒤 목업 명령을 보냅니다.

```bash
adb shell am start --user 10 -n com.galrae.app/.MainActivity
```

별도 터미널에서 로그를 열어 둡니다.

```bash
adb logcat -s GALRAE/MockCmd GALRAE/MockGroup GALRAE/RouteFlow GALRAE/Route GALRAE/AutoStop GALRAE/Speech
```

**조작 구분:** `dest`, `soc` 등은 다른 차량의 행동·상태를 재현합니다. `sheet-primary`, `accept-wp` 등은 내 차 사용자의 응답을 대신합니다. `my-*`와 경로 수락 명령은 **실제 Pleos 내비게이션을 변경**합니다.

확인 시트와 일부 상세 화면 버튼은 UI에 연결되지 않아 adb로 로직을 확인합니다. 화면에서 보이는 자동 제안 카드의 수락은 응답 저장과 실제 내비 요청을 구분해서 확인해야 합니다.

## 1. 이동 정보 확인

**상황:** 언니네는 경포해수욕장으로 목적지를 바꾸고, 부모님은 횡성휴게소에 들르기로 합니다. 그룹에 함께 가자는 제안은 보내지 않습니다.

**준비:** 가상 차량을 `reset`한 뒤 메인 차량 목록을 엽니다. 초기화 명령은 문서 하단에 있습니다.

**흐름:** 가상 차량 경로 변경 → 목록 갱신 → 차량 탭 → 상세 경로 확인

```bash
adb shell am broadcast --user 10 -a com.galrae.app.MOCK --es c dest --es a 'sister:경포해수욕장'
adb shell am broadcast --user 10 -a com.galrae.app.MOCK --es c add-wp --es a 'parents:횡성휴게소'
```

**확인:** 언니네 상세의 목적지는 경포해수욕장, 부모님 상세의 경유지는 횡성휴게소입니다. 내 차 경로는 그대로이며 목적지 변경 제안은 생성되지 않습니다.

## 2. 목적지 변경 제안

**상황:** 강릉역으로 가던 언니네가 경포해수욕장으로 목적지를 바꾸고 내 차에도 함께 가자고 제안합니다.

**준비:** `reset` 후 내 차 목적지를 강릉역으로 설정하고 내비 반영을 기다립니다.

**흐름:** 언니네 변경·제안 → 내 차 수신 → 사용자 수락 → 내 차 내비 변경

```bash
# 다른 차량의 행동 재현
adb shell am broadcast --user 10 -a com.galrae.app.MOCK --es c propose-dest --es a 'sister:경포해수욕장'

# 수신 후 5초 안에 실행: [목적지 변경하기]를 대신하는 응답
adb shell am broadcast --user 10 -a com.galrae.app.MOCK --es c sheet-primary
```

**확인:** `GALRAE/RouteFlow`에서 제안 수신과 수락 로그, `state`에서 내 응답의 `ACCEPTED`, 실제 내비에서 경포해수욕장 목적지를 확인합니다. 현재 확인 시트는 화면 표시 대신 로그로 확인합니다.

**다른 분기:** 같은 준비를 다시 한 뒤 `sheet-primary` 대신 `sheet-secondary`를 보내면 거절입니다. 응답 없이 5초가 지나면 만료되며 응답은 `PENDING`으로 남습니다. 두 경우 모두 내 차 목적지는 강릉역을 유지합니다.

**보내는 쪽 확인:** 내 차 내비 UI에서 직접 목적지를 바꾸면 변경 감지 로그가 발생합니다. 그 직후 `sheet-primary`를 보내면 그룹 제안을 생성하고 가상 멤버들이 응답합니다. 앱 명령 `my-dest`는 사용자 직접 변경으로 취급하지 않으므로 이 테스트를 대신할 수 없습니다.

## 3. 여기로 가기·같이 들르기

### A. 다른 차량의 목적지로 가기

**상황:** 언니네 목적지를 확인한 내가 같은 목적지로 이동하기로 합니다.

**준비:** `reset` 후 내 차 목적지를 강릉역으로 설정합니다. 아래 첫 명령으로 언니네 목적지만 경포해수욕장으로 바꿉니다.

**흐름:** 언니네 목적지 변경 → 상세의 [여기로 가기] 동작 → 변경 확인 → 내 차 내비 변경

```bash
adb shell am broadcast --user 10 -a com.galrae.app.MOCK --es c dest --es a 'sister:경포해수욕장'

# 현재 상세 화면 버튼을 대신하는 명령
adb shell am broadcast --user 10 -a com.galrae.app.MOCK --es c follow --es a '경포해수욕장'

# 5초 안에 [목적지 변경하기]
adb shell am broadcast --user 10 -a com.galrae.app.MOCK --es c sheet-primary
```

**확인:** 내 차 내비 목적지가 경포해수욕장으로 바뀝니다. 이미 내 목적지인 장소에는 확인 시트를 만들지 않습니다. `sheet-secondary` 또는 만료 시 기존 목적지를 유지합니다.

### B. 다른 차량의 경유지에 함께 들르기

**상황:** 언니네가 들르는 문막휴게소에 나도 들르기로 합니다.

**준비:** `reset` 후 내 차는 강릉역 안내 중이고, 문막휴게소가 내 경유지에 없어야 합니다. 빈 경유지 슬롯을 하나 이상 확보합니다.

**흐름:** 언니네 경유지 확인 → [같이 들르기] 동작 → 내 경유지 추가

```bash
adb shell am broadcast --user 10 -a com.galrae.app.MOCK --es c join-wp --es a 'sister:문막휴게소'
```

**확인:** 내 목적지는 강릉역을 유지하고 경유지에 문막휴게소가 추가됩니다. 별도 확인 없이 추가하며, 두 슬롯이 이미 차 있으면 아래 교체 흐름으로 넘어갑니다. 현재 상세 버튼은 adb 명령으로 대신합니다.

## 4. 경유지 제안·교체

**상황:** 언니네가 횡성휴게소에서 모이자고 제안하고, 내가 수락해 경유지에 추가합니다.

**준비:** `reset` 후 내 차는 강릉역 안내 중이어야 합니다. 횡성휴게소가 이미 경유지에 있다면 다른 시연 장소로 바꿉니다.

**흐름:** 합류 장소 제안 → 내 차 수락 → 빈 슬롯에 추가 / 꽉 찼으면 교체 → 내비 요청·응답 저장

```bash
adb shell am broadcast --user 10 -a com.galrae.app.MOCK --es c meetup --es a 'sister:횡성휴게소'

# 5초 안에 최신 경유지 제안 수락
adb shell am broadcast --user 10 -a com.galrae.app.MOCK --es c accept-wp --es a x
```

**확인:** 내 차 목적지를 유지하면서 횡성휴게소가 경유지에 추가되고, `state`에 내 수락 응답이 저장됩니다. `x`는 가장 최근 경유지 제안을 선택합니다. 화면 카드에서의 응답 저장만으로 내비 반영까지 확인한 것으로 보지 않습니다.

**교체 분기:** 내 경유지가 이미 두 개라면 `accept-wp` 후 교체 시트 로그가 발생합니다. 시트가 열린 동안 아래 명령으로 1번을 교체합니다. 두 번째 슬롯은 `2`를 사용합니다.

```bash
adb shell am broadcast --user 10 -a com.galrae.app.MOCK --es c sheet-replace --es a 1
```

교체 후 경유지는 두 개를 유지하고, 선택한 슬롯만 새 장소로 바뀌어야 합니다. 교체 시트에서 `sheet-secondary`를 보내면 거절하고 기존 경유지를 유지합니다. 이미 포함된 장소를 수락하면 중복 추가 없이 응답만 저장합니다.

## 5. 차량 상태 기반 자동 제안

**상황:** 일행의 배터리·연료가 부족하거나 운전 시간이 길어져 앱이 적절한 휴식 장소를 먼저 제안합니다.

**준비:** 카카오 키·네트워크를 확인하고 내 차 목적지를 강릉역으로 맞춥니다. **아래 조건은 각각 앱을 재시작한 뒤 하나씩 테스트**합니다. 앱 실행 직후 다른 자동 제안이 만들어졌다면 만료를 기다립니다.

**흐름:** 상태 변경 → 조건 감지 → 카카오 후보 검색 → 추천 계산 → 자동 제안 카드 → 수락·거절

| 테스트 | 바뀌는 데이터 | 기대하는 추천 |
|---|---|---|
| 배터리 부족 | 언니네 SOC 62% → 15% | 충전소 |
| 연료 부족 | 부모님 연료 48% → 15% | 주유소 |
| 장시간 운전 | 언니네 운전 시작 시각 → 2시간 전 | 휴게소 |

```bash
# 배터리 부족
adb shell am broadcast --user 10 -a com.galrae.app.MOCK --es c soc --es a 'sister:15'
```

```bash
# 연료 부족: 내연기관 차량도 명령 이름은 soc
adb shell am broadcast --user 10 -a com.galrae.app.MOCK --es c soc --es a 'parents:15'
```

```bash
# 장시간 운전
adb shell am broadcast --user 10 -a com.galrae.app.MOCK --es c long-drive --es a sister
```

**확인:** 검색 완료 후 메인 상단에 상태에 맞는 자동 제안 카드가 나타납니다. 추정 도착·대기 정보와 충전·주유의 시설 미검증 표시를 확인합니다. 카드에서 수락·거절 후 `state`로 응답을 확인합니다. 내비 요청까지 확인하려면 카드로 먼저 응답하지 말고, 제안이 유효할 때 시나리오 4의 `accept-wp`를 사용합니다.

**다른 분기:** 자동 제안은 생성 후 15초가 지나면 응답할 수 없습니다. 후보가 없거나 검색에 실패하면 카드 대신 로그를 확인합니다. 동일 차량·조건의 재시도 간격은 20분이며 `reset`만으로 해제되지 않습니다. 다른 에너지 부족 상태가 남아 있으면 휴식보다 충전·주유를 먼저 처리할 수 있습니다.

**ETA 간격:** 모든 참여 차량에 목적지 ETA가 있고 차이가 10분 이상이면 앞차 대상 대기 장소를 자동 제안합니다. 내 차도 실제 내비 안내 중이어야 평가할 수 있습니다. 현재 `lag` 등 ETA 임의 변경 명령은 없어, 원하는 간격을 adb 한 번으로 지정하는 테스트는 지원하지 않습니다.

## 6. 장소 추천 결과 조회

**상황:** 사용자 제안이나 차량 상태 변경 없이 검색·추천 계산만 확인합니다.

**준비:** 가상 차량을 `reset`하고 내 차 목적지를 강릉역으로 맞춥니다. 카카오 키·네트워크가 필요합니다.

**흐름:** 검색 유형 지정 → 실제 후보 검색 → 추천 순위·추정 시간 로그 확인

```bash
adb shell am broadcast --user 10 -a com.galrae.app.MOCK --es c recommend --es a cafe
```

**확인:** `GALRAE/MockCmd`에서 검색 건수·추천 장소·추정 도착·대기 시간을 확인합니다. `cafe` 대신 `food`, `rest`, `charger`, `fuel`을 사용할 수 있습니다. 이 명령 자체는 제안·응답·내비 변경을 만들지 않습니다.

추천 시간은 직선거리 기반 추정값입니다. 실제 교통·우회 시간이나 충전 시설 적합성·에너지 도달 가능성을 검증한 결과가 아닙니다.

## 7. 메시지 수신·TTS 읽기

**상황:** 언니네가 “다음 휴게소에서 쉬자”는 메시지를 보냅니다.

**준비:** 앱 화면을 열어 두고 STT 입력을 종료합니다. 이 테스트는 텍스트를 직접 주입하므로 마이크 입력이 필요하지 않습니다.

**흐름:** 가상 차량 메시지 주입 → 내 차 수신 → 말풍선·전달 토스트 → TTS 읽기

```bash
adb shell am broadcast --user 10 -a com.galrae.app.MOCK --es c say --es a 'sister:다음 휴게소에서 잠깐 쉬었다 가요'
```

**확인:** 발신자가 언니네인 수신 메시지와 TTS 읽기를 확인합니다. 전달 토스트는 TTS 시작·완료에 맞춰 표시·종료됩니다. 수신 텍스트를 내 차 TTS로 읽는 테스트이며, 실제 차량 간 통신·녹음 원음 전송 테스트는 아닙니다.

**직접 입력:** STT 발신을 확인하려면 README의 마이크 설정 후 화면의 메시지 버튼으로 말합니다. 버튼 재탭 또는 최대 15초 입력 종료 후 텍스트가 전송되는지 확인합니다. 메인에서는 그룹 전체, 차량 상세에서는 해당 멤버에게 전송합니다.

## 공통 초기화·상태 확인

### 가상 차량 초기화

```bash
adb shell am broadcast --user 10 -a com.galrae.app.MOCK --es c reset
adb shell am broadcast --user 10 -a com.galrae.app.MOCK --es c state
```

가상 차량·제안·텍스트 메시지를 초기화합니다. 내 차 실제 경로·자동 추천 재시도 기록은 유지합니다. 진행 중인 확인 시트가 있다면 만료 후 다음 테스트를 시작합니다. `state` 결과는 `GALRAE/MockGroup` 로그에 출력됩니다.

### 자동 추천 기록까지 초기화

```bash
adb shell am force-stop --user 10 com.galrae.app
adb shell am start --user 10 -n com.galrae.app/.MainActivity
```

앱이 열린 것을 확인한 뒤 명령을 보냅니다. 내비 경로는 별도로 유지되므로 필요하면 목적지를 강릉역으로 되돌립니다.

### 내 차 경로 준비

실제 내비 UI에서 경로를 설정하거나 다음 명령을 사용합니다. **각 명령 후 내비 반영을 확인한 뒤 다음 명령을 실행**합니다.

```bash
# 목적지 설정 — 기존 경유지 중 좌표를 아는 곳은 유지
adb shell am broadcast --user 10 -a com.galrae.app.MOCK --es c my-dest --es a '강릉역'
```

```bash
# 빈 슬롯이 있을 때 경유지 추가
adb shell am broadcast --user 10 -a com.galrae.app.MOCK --es c my-wp --es a '문막휴게소'
```

```bash
# 1번 슬롯에 기존 경유지가 있을 때 교체
adb shell am broadcast --user 10 -a com.galrae.app.MOCK --es c my-wp-replace --es a '1:횡성휴게소'
```

경유지를 비우려면 내비 UI에서 제거합니다. `my-dest`는 경유지 초기화 명령이 아닙니다. 기존 경유지 좌표를 모르면 재전송 시 빠질 수 있으므로 로그와 내비를 함께 확인합니다. 경로 요청 확인 대기는 최대 30초이며, 요청 전송과 실제 반영 성공은 구분합니다.

사용 가능한 장소: **강릉역, 문막휴게소, 경포해수욕장, 강릉중앙시장, 횡성휴게소, 평창휴게소**. 이름은 고정 목업 좌표를 가리키며 카카오 추천 검색 결과와 별개입니다.

## 문제 해결

| 증상 | 확인할 사항 |
|---|---|
| 명령 후 변화 없음 | 앱 실행·user 10·`GALRAE/MockCmd` 오류 확인. broadcast 완료는 처리 성공을 뜻하지 않음 |
| 시트 없음·수락 불가 | 목적지·합류 제안은 5초, 자동 제안은 15초 만료. 이미 응답했는지도 확인 |
| 자동 추천이 다시 나오지 않음 | 앱 재시작으로 20분 재시도 기록 초기화 |
| 추천 실패·후보 없음 | 카카오 키·네트워크·공통 목적지와 로그 확인 |
| 내비 경로가 바뀌지 않음 | 내비 계산 완료·권한·네트워크, `GALRAE/Route`의 실패·시간 초과 로그 확인 |
| 화면에 버튼·시트가 없음 | UI 미연결 동작인지 해당 시나리오에서 확인하고 adb로 로직 테스트 |
